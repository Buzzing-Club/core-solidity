## 1) TradeManager / TradeManager2

### 1.1 buyNo 数量错位修复

问题：`buyNo()` 里原先由多组外部参数共同控制数量，可能导致拆仓、转移、记账不一致。

修复：在函数内部统一使用 `params.amountIn` 作为唯一数量源，避免外部参数不一致导致仓位和风险错账。

已统一替换的动作包括：

- `splitPosition(..., amount)` -> `params.amountIn`
- NO 侧 `safeTransferFrom(..., value)` -> `params.amountIn`
- NO token 转给用户数量 -> `params.amountIn`
- YES 对冲腿 `safeTransferFrom(..., value)` -> `params.amountIn`

### 1.2 费用口径调整（去除 LPfee / bufferFunds 参与风险与 PnL）

根据最新方案：手续费全部走 `feeAdapter`，不再在 TradeManager 内通过 `LPfee` 和 `bufferFunds` 参与资金与 PnL 模型。

已调整为：

- `sellYes/sellNo` 的 `_handlePnl(...)` 仅使用交易真实 `pnl`
- 去除 `LPfee`、`bufferfee` 的本地累加逻辑
- `_availableFunds()` 不再 `+ bufferFunds`

说明：`bufferFunds` 状态变量保留（存储兼容考虑），当前按闲置变量处理。

### 1.3 _handleInterest 负值安全处理

问题：`interest` 可能为负，直接做 `uint256` 转换会 revert。

修复策略：

- 当前不再更新 `yieldInterest`（保持该变量闲置，避免负值强转）
- 继续执行 `_handlePnl(-interest)`，保持盈亏结算链路

### 1.4 userWithdraw 后同步收益基线

在 `userWithdraw()` 触发 `yieldProtocol.withdraw(...)` 后，新增 principal 快照同步：

- 读取当前 `shares`
- 通过 `convertToAssets(shares)` 更新 `yieldPrincipalUsed`

目的：避免后续 `_handleInterest()` 使用陈旧基线，导致利息 delta 偏差。

### 1.5 buy 侧恢复静态手续费（不含动态 fee）

按最新决定，`buyYes / buyNo` 重新收取静态手续费（来自 `feeAdapter.poolTotalFeeRatio(pool)`），但不引入动态 fee。

- `buyYes`
  - 用户输入 `params.amountIn`
  - 先计算静态 fee：`totalFeeAmount = params.amountIn * feeRatio / FEE_SCALE`
  - 用 `amountInAfterFee = params.amountIn - totalFeeAmount` 参与 swap
  - 静态 fee 转入 `feeAdapter`，并 `recordFee(...)` 分账

- `buyNo`
  - 先完成 YES 对冲腿 swap，得到用户基础成本 `userCost = params.amountIn - amountOut`
  - 再叠加静态 fee：`totalUserDebit = userCost + totalFeeAmount`
  - 用户实际补款改为 `totalUserDebit`
  - `usdSpent / buyNoUSD / maxAmount` 校验口径同步改为 `totalUserDebit`
  - 静态 fee 转入 `feeAdapter`，并 `recordFee(...)` 分账

已验证：

- `test/trade/tradeyes.spec.js` 通过
- `test/trade/tradeno.spec.js` 通过

## 2) tBLP / sBLP

### 2.1 PnL 与 totalDeposited 同步

问题：`distributePnl/reclaimPnl` 只改价格，不改 `totalDeposited`，会导致 withdraw 路径账本不一致。

修复：

- `distributePnl(assets)`：`totalDeposited += assets`
- `reclaimPnl(assets)`：`totalDeposited -= assets`

并增加保护：

- `require(totalSupply() > 0, "NO_SUPPLY")`
- `require(totalDeposited >= assets, "INSUFFICIENT_TOTAL_DEPOSITED")`（reclaim 路径）

效果：share price、真实资产、`totalDeposited` 三者口径一致，避免下溢和回退。

## 3) PreTrading

语义修正：将原误导性的 `usdc` 语义改为 `usdb`（包括构造参数命名），并保持 oracle 机制不变。

新增风控约束：

- 最小下注金额：`3 USDB`
  - 新增常量：`MIN_BET_USDB = 3 * 1e6`
  - `deposit()` 增加校验：`amount >= MIN_BET_USDB`

- 撤回后的剩余持仓限制：
  - 在 `withdraw()` 中，撤回后剩余金额必须满足：
    - `remaining == 0`（清仓），或
    - `remaining >= 3 USDB`
  - 目的：避免通过“先下 5U 再撤回 3U”制造低于最小门槛的残留仓位
